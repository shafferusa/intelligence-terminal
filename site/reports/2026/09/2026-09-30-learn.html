The Rule Behind Your GPS, Your Thermostat, and Your Streaming Feed

Wednesday, September 30, 2026 · 13 min read

GPS turns satellite timing into a location, a thermostat turns a temperature into a decision, and a streaming service turns your watch history into a recommendation — different machines, doing the same three-and-a-half-century-old kind of math: the function.

Mathematics

Day 3 of 300 · Mathematics 3 of 20 · Functions: the language of change and relationship

The Big Idea

Think about a vending machine. You press B4, and out comes a bag of pretzels — the same bag of pretzels, every single time you press B4. It never sometimes gives you pretzels and sometimes gives you a soda for the same code. That reliability, one input always producing exactly one specific output, is the entire idea behind one of the most important concepts in all of mathematics: the function.

A function is a rule that takes something in (an input) and hands back exactly one thing out (an output), every time, for every allowed input. Day 1 built the number system and introduced proof; Day 2 showed you how to solve an equation for a single unknown number. Today's idea is different in kind: instead of asking “what one number makes this equation true,” a function describes an entire relationship — how an output changes as you feed it different inputs, all at once, as a single object you can study, graph, and reason about.

This is the idea that quietly runs a huge share of the modern world. A GPS chip is running a rule that turns satellite signal timings into a location. A thermostat is running a rule that turns a room's temperature into a decision about whether to fire the furnace. A streaming service is running a (much more complicated) rule that turns your watch history into a ranked list of suggestions. All of them are functions, in the precise mathematical sense this lesson defines.

How It Works

Formally: a function is a rule that connects two sets. The set of allowed inputs is called the domain; the set of outputs the rule actually produces is called the range. The one non-negotiable requirement, the thing that separates a function from just any old relationship between two quantities, is this: every input in the domain must produce exactly one output. Not zero, not two, not “it depends.” One. A rule that sometimes gives an input two different outputs isn't a function — mathematicians just call it a relation, a broader and less useful category.

The other direction is unrestricted, and this trips people up on first contact: two different inputs are completely allowed to share the same output. The vending machine can only ever give one thing for B4, but nothing stops both B4 and C7 from dispensing the same brand of pretzels. Mathematically, f(3) and f(−3) can both equal 9 (they do, for the rule “square the input”) without breaking anything. What's forbidden is one input splitting into two outputs, never two inputs landing on one output.

Once you can plot a function on a coordinate plane — each input on the horizontal axis, its one matching output plotted directly above or below it on the vertical axis — that one-output rule turns into a visual test. Sweep an imaginary vertical line across the graph. If it ever crosses the curve at two points at once, two different outputs are being claimed for the same input, and whatever you've drawn is not a function. This check has a standard name, the vertical line test, and it's exactly the domain/range rule translated into a picture: a circle drawn on a graph fails it (a single x-value hits the circle twice, once on top and once on the bottom), which is the quick way to see that “a circle” is not, itself, a function.

A function doesn't have to show up as an equation to count. The same rule can appear as a formula (“multiply the input by 1.8 and add 32”), as a graph (a line or curve on a coordinate plane), as a table (a list of inputs next to their matching outputs, the way a tide chart lists times next to water heights), or just as a sentence in plain English. All four are the same function, described four different ways; part of getting comfortable with functions is learning to move between these representations, since a table of tide heights and the trigonometric formula that generates it are, mathematically, the identical object.

The word itself is older than you might guess. Gottfried Leibniz — the same mathematician and philosopher who developed calculus independently of Isaac Newton — coined the term functio in a 1673 manuscript, though he used it narrowly at first, for quantities tied to a curve's geometry, like the length of a tangent line at a given point. Over the following decades Leibniz and his correspondent Johann Bernoulli broadened the word until, by around 1700, it meant roughly what it means today: a quantity that depends on another quantity. The compact notation you've probably already seen, f(x), came later still — the mathematician Leonhard Euler introduced it in a 1734 paper, writing “if f(x) denotes any function of x…” It took decades more before that notation became the everyday standard; textbooks weren't using it consistently until the early 1800s.

The definition got one more, more radical upgrade in 1837, from the mathematician Peter Gustav Lejeune Dirichlet. Before Dirichlet, most mathematicians still assumed a “real” function had to be expressible as some kind of formula — an equation you could write down and compute with. Dirichlet's definition dropped that requirement entirely: a function is any rule at all that assigns exactly one output to each input, whether or not anyone can ever write that rule as a tidy equation. To prove the point, he described a genuinely strange rule now called the Dirichlet function: output 1 when the input is a rational number, output 0 when it's irrational — the same rational/irrational split from Day 1. It satisfies every requirement of the definition (every real number is either rational or irrational, never both, so every input gets exactly one output), even though its graph can't be drawn in any ordinary sense — it would look like an infinitely dense scatter of points at height 0 and height 1, with no curve connecting them. Dirichlet's version is the one mathematicians still use today.

Domains matter because not every rule accepts every possible input. The rule “take the square root” is a perfectly good function over the domain of non-negative real numbers, but it simply has nothing to return for an input like −4 (not among the real numbers, at least — that story is for a later lesson): so the domain of that function has to explicitly exclude negative numbers, or the rule breaks. Stating a function's domain is part of stating the function; two rules with the same formula but different domains are, strictly, different functions.

Last piece: how a function's output responds to changes in its input splits functions into two broad families. A linear function changes at a constant rate — every time the input goes up by 1, the output goes up (or down) by the same fixed amount, no matter where you start, which is exactly why its graph is a straight line. Day 2's equations of the form ax + b = 0 describe where a linear function crosses zero. A nonlinear function's rate of change isn't constant — the quadratic functions behind Day 2's quadratic formula are the simplest example: for f(x) = x², going from input 1 to input 2 raises the output by 3 (from 1 to 4), but going from input 2 to input 3 raises it by 5 (from 4 to 9). The rate itself is changing, which is exactly what makes the graph curve instead of running straight.

Key Concepts

Function
A rule that assigns to every input in its domain exactly one output — never zero, never two.
Input / output
The value you feed into a function (input) and the single value the rule hands back (output). Two different inputs are allowed to share an output; one input can never produce two.
Domain
The complete set of inputs a function is allowed to accept. Excluding a value from the domain is often how a rule that would otherwise break (like square-rooting a negative number) stays a valid function.
Range
The set of outputs a function actually produces across its whole domain.
Graph
The picture of a function: every input plotted on one axis against its one matching output on the other. A curve represents a function only if it passes the vertical line test.
Linear vs. nonlinear
Linear: the output changes at a constant rate as the input changes, producing a straight-line graph. Nonlinear: the rate of change itself varies, producing a curve.

Example / Application

Start with a function you've almost certainly used without naming it: converting a temperature between Celsius and Fahrenheit. It's a linear function — a fixed rule, one input (a Celsius reading), one output (the Fahrenheit reading) — and it's exactly the kind of rule a thermostat evaluates constantly to decide what to show you and, in a more elaborate version, whether to turn the furnace on.

Converting Celsius to Fahrenheit: F = 1.8C + 32

Room temperature, 20°C: F = 1.8(20) + 32 = 36 + 32 = 68°F.

Body temperature, 37°C: F = 1.8(37) + 32 = 66.6 + 32 = 98.6°F.

Every Celsius input has exactly one Fahrenheit output, and the output climbs at a constant rate — 1.8°F for every 1°C — which is why this particular function's graph is a straight line.

A thermostat's actual furnace decision is a different, and nonlinear, function of the very same input. Set a target of 68°F, and the rule might be: output “heat on” for any room temperature at or below 66°F, output “heat off” for anything at or above 70°F, and hold the previous state in between (so it doesn't flick on and off every few seconds near the target). That's still a genuine function — every input temperature still gets exactly one output decision — but its rate of change isn't constant at all; it jumps abruptly at two thresholds and sits flat everywhere else. Graphed, it looks like a staircase, not a line: mathematicians call this general shape a step function, one of the more common nonlinear rules in ordinary engineering.

A GPS chip works on the same principle at much higher stakes. Each satellite signal your phone receives carries a timestamp; comparing that timestamp against the phone's own clock gives the signal's travel time, and travel time times the speed of light gives a distance to that one satellite — which by itself only narrows your location down to a sphere of possible points, every point the same distance from that satellite. One satellite's signal is one input producing one distance; add a second satellite and you've narrowed your position to the ring where two spheres intersect; a third narrows it to (almost always) a single point. The whole calculation, from a handful of signal timestamps in to one coordinate out, is a function in exactly today's sense — the same timestamps will always produce the same computed position.

A streaming service's recommendation engine is a function too, just with a vastly larger domain (your entire viewing history, encoded as numbers) and a vastly larger range (a ranked list of shows) — the input/output logic is identical in kind to the thermostat example, even though the rule itself is far too complicated for any person to write down as a single formula, exactly the kind of function Dirichlet's 1837 definition made room for: no one needs to be able to write the equation for it to still be, formally, a function.

Equation / Model

Euler's notation is worth writing out explicitly, because you'll see it in every mathematics lesson from here forward.

y = f(x)

y equals f of x.

x
the input, chosen from the function's domain
f
the name of the rule itself — the specific function being applied (you could just as well call it g or h; f is only a common default)
f(x)
read aloud as “f of x”: the one output the rule f produces when applied to input x — not f multiplied by x, a common first-glance mistake
y
a short name commonly given to that output, especially when graphing, so the graph's two axes can be labelled x and y

“y = f(x)” is doing nothing more exotic than saying “whatever comes out, call it y.” The real content of a function is always in what f actually does — the specific rule, like “multiply by 1.8 and add 32” or “square it.” Once you fix that rule, f(3) is just shorthand for “go plug 3 into the rule and see what comes out,” the same way you'd read a recipe by substituting in whatever ingredient it names.

Why It Matters

Functions are the object mathematics actually studies, far more than any single equation. Day 2 taught you to solve ax² + bx + c = 0 for the specific inputs where a quadratic function happens to equal zero — useful, but it only asks about one output value. Once you have the function itself, f(x) = ax² + bx + c, you can ask a much richer set of questions: how fast is it changing at any given input, where is it at its largest or smallest, what shape does its whole graph trace out, how does changing a, b, or c reshape the entire curve rather than just one root. That shift, from solving for a single number to studying an entire rule, is what opens the door to almost everything else this subject will cover.

It also matters far outside a classroom. Any system that has to reliably turn one measurable thing into another — a sensor reading into a control decision, a set of satellite delays into a coordinate, an account's history into a recommendation — is, underneath its engineering, implementing a function, and every guarantee that system can make (it will never give you two different answers for the same input; it always terminates with exactly one result) is really a guarantee about the mathematical object this lesson just defined.

One more habit worth building now: functions can feed into each other. Take the Fahrenheit-Celsius rule from the worked example, and imagine piping its output straight into a second rule — say, one that decides whether to display a “wear a coat” alert whenever the Fahrenheit reading drops below 40. The temperature-to-alert pipeline is itself a function, built entirely out of chaining two simpler functions together: a Celsius input goes in, and a single yes/no output comes out the far end, having passed through both rules along the way. That chaining, called composition, is how genuinely complicated systems — a recommendation engine, a GPS receiver, a thermostat's full control loop — get built at all: not as one impossibly intricate formula, but as ordinary functions, each simple on its own, linked so one's output becomes the next one's input.

Remember These
  • A function assigns exactly one output to every input in its domain — never two, though two different inputs can share the same output.
  • Domain = the inputs a function is allowed to accept; range = the outputs it actually produces.
  • “y = f(x)” (Euler, 1734) just means “the output y is whatever the rule f produces from input x.”
  • Linear functions change at a constant rate (straight-line graphs); nonlinear functions change at a varying rate (curved or stepped graphs).
  • Dirichlet's 1837 definition dropped the old requirement that a function be expressible as a formula — any consistent one-output-per-input rule qualifies, however strange.
Think About It

A function guarantees exactly one output for every input — but nothing in the definition guarantees the reverse. Knowing the thermostat's furnace is “on” doesn't tell you the exact room temperature, only that it's somewhere at or below 66°F. Knowing f(x) = x² equals 9 doesn't tell you whether the input was 3 or −3. What would have to be true of a function's rule for the reverse guarantee to hold too — for every output to trace back to exactly one input, with no ambiguity?
