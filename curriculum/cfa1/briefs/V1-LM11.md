## Core principles
- **More data is only useful if it is trustworthy.** Digitization lets text, images and sensor feeds sit beside numbers, and fintech pushes managers to use ML to find opportunities, optimize portfolios and manage risk. The risk is the model's reliability: small errors in data, entry or design can swing results. The conclusion fails when inputs are biased, missing or noisy (pp.573–577).
- **Big data = volume, velocity, variety, plus veracity.** The first three describe size, speed and formats; the fourth, reliability, matters when data are used to infer or predict. Structured data fit tables, semi-structured data carry tags (for example formatted news), unstructured data have no table form (text, audio, video, sensors) (pp.578–580).
- **Alternative data come from individuals, business processes and sensors.** Business-process data can act as a timely indicator of performance, where traditional corporate metrics are periodic and lag. The cost is legal and ethical exposure (web scraping, personal data, differing national rules) plus selection bias, gaps and cleaning effort (pp.581–583).
- **Financial data are awkward.** They are fast and large, time-dependent, noisy, non-stationary, non-linear, seasonal, fat-tailed (extremes more frequent than a normal curve implies, so risk is understated) and sometimes sparse (for example in emerging markets). A model built on a relationship that later shifts will fail out of sample (pp.583–584).
- **ML finds a pattern, then applies it, and must be judged on data it has not seen.** Training data fit the model, validation data tune it, test data give the final unbiased check. Overfitting means fitting noise: training error far below test error. Underfitting means missing real structure. For time-ordered data, a random split lets the future leak into training; use chronological or rolling-window splits (pp.585–588).
- **Choose the learning type by what you have.** Supervised needs labelled data and predicts or classifies. Unsupervised has no labels and finds groups or anomalies, but results are hard to judge. Reinforcement learns from rewards in sequential decisions and is sensitive to a badly set reward. Deep learning uses many-layer neural nets for complex patterns but needs large data and computing power and is a black box (pp.589–591).
- **Text tools are powerful but need oversight.** NLP turns filings, calls and central-bank text into sentiment signals. LLMs generate fluent text but may misstate numbers, so pair them with traditional models and human review. Generative AI creates new data that resembles real data; it is not Monte Carlo or bootstrapping (pp.592–594).
- **Process and tools.** Data flow: capture, curation (cleaning), storage, search, transfer. Pick the visualization and tool to match structured versus unstructured data (pp.595–598).

## Vocabulary
- Quantitative / qualitative data — numeric / non-numeric inputs to decisions (p.573).
- Fintech — new technology applied to designing and delivering financial products and services (p.584).
- Data science — the whole pipeline from collecting and cleaning data to modelling and interpreting it (p.576).
- Financial data science — data science applied to financial data and contexts, needing finance knowledge (p.576).
- Data mining — algorithmic search for patterns in data (pp.577–578).
- Big data / four Vs — volume, velocity, variety, veracity (pp.578–579).
- Structured / semi-structured / unstructured — tabular / tagged narrative / no table form (p.580).
- Alternative data — non-traditional data from individuals, business processes and sensors (p.581).
- Internet of Things; web scraping — networked devices; automated extraction from websites, with privacy risk (p.582).
- High-frequency data; low latency — very fine time stamps; minimal processing delay (pp.576, 595).
- Data lake; distributed computing — raw data stored in original form; work spread over many machines (pp.583–584).
- Non-stationarity; fat tails — statistical properties that drift over time; extremes more common than normal (p.584).
- Training / validation / test set — fit / tune / final out-of-sample check (pp.585–586).
- Data leakage — information from the evaluation period contaminating training (p.586).
- Overfitting / underfitting — fitting noise / missing real patterns (p.588).
- Supervised / unsupervised / reinforcement learning — labelled / unlabelled / reward-driven (pp.589–590).

- NLP / LLM / generative AI — text interpretation / transformer-based language model / creation of new data (pp.592–594).
- SQL, SQLite, NoSQL — structured server database / embedded mobile database / unstructured data store (pp.597–598).

## Formulas
- **Bayes:** P(Pattern|Data) = P(Data|Pattern) × P(Pattern) / P(Data). Symbols: posterior probability of the pattern given the data; likelihood of the data given the pattern; prior probability of the pattern; probability of the data across all hypotheses. Dimensionless probabilities. Assumes a sensible prior. Intuition: update belief in a pattern by how well it explains what you saw (p.577, PDF 587). Illustrative only.
- **Overfitting signature:** Error_train << Error_test (error of model f(x) on training versus test data). A diagnostic, not a calculation (p.577, PDF 587).
- Split rules of thumb: standard 60–80 / 10–20 / 10–20 percent train/validation/test; larger datasets 70–80 / 10–15 / 10–15; smaller datasets 60–70 / 15–20 / 15–20 (p.586, PDF 596).

## Traps
- Overfitting is the too-complex case; underfitting is too simple. Test error well above training error means overfit.
- Random splitting is wrong for time series; keep chronological order to avoid leakage.
- Validation tunes the model; the test set is the last out-of-sample check.
- Big data is not just volume; remember velocity, variety and veracity.
- Tagged financial news is semi-structured, not unstructured.
- ML and LLMs still need human judgment (cleaning, bias, review, number checking).
- Generative AI learns patterns and creates data; do not equate it with Monte Carlo or bootstrapping.

1. 5,000 labelled observations, 70/15/15 split: training 3,500, validation 750, test 750 (total 5,000). With 60/20/20: 3,000/1,000/1,000, so training loses 500 and each evaluation set gains 250.
2. 60 monthly returns, Jan 2020 to Dec 2024: train on the first 42 months (to Jun 2023), validate the next 9 (Jul 2023 to Mar 2024), test the last 9 (Apr to Dec 2024); 42+9+9 = 60. A random split would train on 2024 and test on 2021, leaking the future.
3. Classifier A has 1.0% training and 6.0% test misclassification (gap 5.0 points); B has 3.0% and 3.5% (gap 0.5). A is overfit. If A is simplified to 3.5% and 4.0%, it generalizes better despite the worse training fit.
